Javascript matrix math

Javascript

This website uses small doses of Javascript, like in user interaction with animations as discussed here.

But it can also used to do some pretty complex math.

solving matrix equations

The sections on state space analysis of airplane stability and control models routinely use matrix equations. Solving these equations goes beyond the capa­bili­ties of the typical pocket calculator.

  Having done this work by hand in my younger years, and later in life by the likes of Matlab© and its precursors and successors, it is with considerable relief that I find that any simple browser can do these calculations today.

  The language of choice is Javascript, and the library of choice is Math.js. However, as seems unavoidable in the computing world, both have a surprising history of quirks. Some caveats and workarounds are given below.

native Math in Javascript

Javascript has some native capabilities for everyday math and arithmetic, but it soon runs out of steam when the numbers get complex, and when the equations get organised in matrices. Statements like a = Math.sqrt(2) are valid for integers and floating point numbers, but not for complex numbers or matrices. These Math functions with a capital "M" are part of the Javascript language definition, but still they must be preceded by the Math prefix unless special tricks are used.

math.js

There is a universally accepted library extending Javascript to more complicated math. It is called math.js. Interestingly, the functions from this library must be preceded by the same word math , but with a lowercase "m".

  The standard Javascript Math.sqrt() will return NaN when the argument is negative, like for Math.sqrt(−4). By con­trast, math.sqrt(−4) will dutifully return the complex root 2 i. The math library also supports matrix operations and many other useful functions.

using math.js locally or offline

There are several ways of "installing" math.js on a computer so it can be used by browsers and other pro­grams or from the command line. But it can also be used as an external library, by referencing the math.js website.

  Using math.js on a web page like this has its dangers. If it relies on "installed" code, then it may not run on someone else's computer, or it may run an incompatible version. If the external option is used, it may not run offline.

  My preferred solution is to keep a trusted copy of the Javascript code in the same directory as the web pages using it, whether online or offline. On this website, the math.js code is located here.

specific versions of math.js

The software world has a long and sad history of ( near ) free software suddenly disappearing behind paywalls by companies buying up or otherwise killing the competition, and of unsollicited changes in syntax breaking old code when running a later version.

  For the moment it looks like Javascript and math.js are safer than most, but precisely in the code used below there was a change in the interface of the math.eigs() function that broke existing code at the time.

  This website uses math.js version 15.2.0 in a local copy, in an attempt to keep its functionality unaffected by the vagaries of the outside world.

eigenvalues and eigenvectors in Math.js

This website use matrix eigenvalues and eigenvectors in state space analysis of aircraft. It will be helpful to show the relevant Math.js syntax, and some of its idiosyncrasies.

  A matrix can be defined as a standard two-dimensional Javascript array : 

let A = [ [ 1 2 ]
          [ 3 4 ] ];
(1)

The eigenvalues and eigenvectors are obtained by a single call to the relevant Math.js routine : 

let E  = eigs( A);
(2)

It would have been nice if the outputs had been an array of eigenvalues and a matrix of eigenvectors, but no such luck. Instead, the output is an array of objects, one per eigenvalue. These objects each have two properties, called value and eigenvector. It is best to ignore the first property, because it is repeated in the second. The eigenvectors property itself has two properties of its own, one of them again called value, and the other one vector.

  We will show later how to convert these software objects to the more conventional matrix-vector form. If we just want to pick out one eigenvalue and its eigenvector, then a simplistic way of doing it is this :

  Note somewhere that math.js 1D vectors are neither row vectors nor column vectors. They are sort of neutral. Math.js chooses the most likely interpretation when they are passed to a function, unless the interpretation is forced by the definition of the vector as a 2D matrix with either row or column dimension. 

let ED_0 = E[0].eigenvectors.value;
let EV_0 = E[0].eigenvectors.vector;
(3)

The index [ 0 ] selects the first eigenvalue and its associated eigenvector. In keeping with the unfortunate "C" language heritage, the indices of an array of length N run from 0 to N − 1 in Javascript.

  There are as many eigenvalues and eigenvectors as the size N of the system matrix, but the ones having an imaginary component come in complex pairs, a ± i b.

the order of the eigenvalues

The eigs( ) function lists the eigenvalues sorted from small to large by their absolute values. In complex pairs the one with the positive imaginary part is listed first. This is an arbitrary but reasonable choice. It is up to the human user to physically interpret each eigenvalue and its eigenvector, and often the slowest phenomena ( lowest eigen­values ) are a good place to start.

the size and phase of the eigenvectors

Each eigenvector has its own distinctive "shape", namely the ratio between its elements. However, the overall size is arbitrary. If [ 0, 1 ] is an eigenvector, then so is [ 0, 2 ]. For instance, in a first order system ( like a damper ), all elements of the eigenvector will decay at the same rate with time, and in fact [ 0, 2 ] will soon decay to [ 0, 1 ] and further, without changing the shape.

normalizing the eigenvector

Since the size of an eigenvector is arbitrary, we can scale it to any value for easier human interpretation. Some packages scale the eigenvector to have an overall "vector length" of 1. This helps to give readable numerical values, but apart from this this it is as arbitrary as any other choice. Math.js as far as I can see does not seem to bother giving the eigenvectors any specific scale.

  It is often the case that one of the elements in the state has an easy physical interpretation, like an externally visible position or angle. In such cases, it is a good option to scale the vector to give 1 in this element.

  Suppose we wish to scale the vector relative to its element number [ 4 ] ( with unfortunately, array index [ 3 ] ). Continuing the example given in (3), we only need to do this : 

// scale EV_0 to its 4th element ( index [3] )
EV_0 = math.divide( EV_0, EV_0[3] );
(4)

We keep using the same variable name here because after all it still is the same eigenvector, but a new name can be used too. The reason to use math.divide ( ) instead of the simple fractional slash is that this allows the elements to be complex numbers. Unlike in Matlab ©, the simple slash does not divide complex numbers in standard Javascript.

complex eigenvalues

Eigenvalues can come in complex pairs, and then they will typically have complex eigenvectors. Complex eigenvalues describe oscillating systems. The real part of the eigenvalue represents a decay with time ( if it is negative; otherwise it is a growth rate ). The imaginary part is the oscillation frequency of the motion, expressed in radians per second.

  The elements of the eigenvector do not necessarily oscillate in sync. They may be out of "phase" with each other.
